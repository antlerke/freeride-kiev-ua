# Бекенд сайту FreeRide

WordPress із власною темою й плагіном. Elementor не використовується:
сторінки редагуються полями, тож макет зламати неможливо, а сторінка
вантажить рівно те, що в ній є.

## Запуск

```bash
cd wp
docker-compose up -d     # WordPress + MariaDB
./init.sh                # ядро, плагіни, мова, права — ідемпотентно
./seed.sh                # курси, прайс, сторінки, меню — теж ідемпотентно
```

Сайт: http://localhost:8080 · адмінка: http://localhost:8080/wp-admin/
Логін і пароль — у `wp/.env.local` (створюється сам, у git не потрапляє).

Знести все разом із базою: `docker-compose down -v`.

## Що де

| | |
|---|---|
| `content/plugins/freeride-core/` | **вміст**: тип запису «Курс», поля, прайс, SEO-розмітка |
| `content/themes/freeride/` | **оформлення**: шаблони, CSS, JS, спрайт іконок |
| `seed.php` | первинне наповнення — курси, ціни, сторінки, меню |
| `../deploy/redirects/` | карта 301/410 зі старого сайту |

Чому курси в плагіні, а не в темі: якщо оголосити тип запису в темі,
то зміна теми прибирає з сайту всі курси — записи лишаються в базі,
але WordPress більше не знає такого типу. У плагіні вони переживуть
і зміну теми, і повне переписування оформлення.

## Прайс

Єдине джерело — тип запису «Курс» плюс сторінка **Курси → Ціни**.
Звідти збирається `/wp-json/freeride/v1/pricing` тією самою схемою,
якою раніше віддавався статичний `docs/data/pricing.json`. Саме тому
калькулятор переїхав на адмінку без жодної правки в `calc.js`.

Будь-яка зміна курсу чи прайсу скидає кеш відповіді автоматично.

## Сторонні плагіни

| | навіщо |
|---|---|
| Secure Custom Fields | поля. Форк ACF від Automattic, безкоштовний, той самий `get_field()` |
| Polylang | українська в корені, англійська під `/en/` |
| Yoast SEO | SEO-поля. Плюс наші змінні `%%fr_price%%`, `%%fr_hours%%`, `%%fr_code%%` для шаблонів заголовків |

Поля описані кодом у `inc/fields.php`, а не накликані в адмінці: опис
лежить у git, їде на бойовий сервер разом із релізом і не потребує
перенесення бази.
